## ส่วนที่ 1 — โครงสไลด์ (14 สไลด์)

> แต่ละสไลด์: **หัวข้อ** / เนื้อบนสไลด์ (bullet สั้น) / 🗣️ *สิ่งที่พูด*

### สไลด์ 1 — หน้าปก
- ชื่อโครงงาน: **ระบบบำรุงรักษาเชิงป้องกัน (PM Web Application)**
- ชื่อผู้จัดทำ / รุ่น workshop / วันที่
- 🗣️ *แนะนำตัว + ชื่อระบบ 1 ประโยค*

### สไลด์ 2 — ที่มา & ปัญหา
- อุปกรณ์ไอที (เครื่องพิมพ์/คอมพิวเตอร์/เครือข่าย) ต้องบำรุงรักษาตามรอบ
- ปัญหาเดิม: จดมือ/Excel กระจัดกระจาย → ลืมรอบ PM, ไม่รู้ว่าใครทำ, หาประวัติยาก
- 🗣️ *ทำไมต้อง "เชิงป้องกัน" — กันเสียก่อนพัง ถูกกว่าซ่อม*

### สไลด์ 3 — ระบบนี้ทำอะไรได้ (ขอบเขต)
- จัดการอุปกรณ์ · บันทึกผล PM + Checklist · แจ้งเตือนถึงรอบ · รายงาน + Excel
- แยกสิทธิ์ผู้ดูแล/ช่าง · บันทึกประวัติทุกการใช้งาน (audit)
- 🗣️ *สรุปภาพรวม 1 สไลด์ ก่อนลงรายละเอียด*

### สไลด์ 4 — Tech Stack & สถาปัตยกรรม
- Frontend: React + TypeScript + Vite + Ant Design
- Backend: Node.js + Express + Prisma · Database: **MS SQL Server**
- Export: ExcelJS · Deploy: **Docker (คำสั่งเดียว)**
- โครงสร้าง monorepo: `server/` + `web/` แยกอิสระ
- 🗣️ *เหตุผลที่เลือก: เขียนไว, type-safe, รองรับ MSSQL, รันง่าย*

### สไลด์ 5 — ฐานข้อมูล (ER Diagram)
- ใส่ภาพ ER 7 ตาราง (จาก `docs/DESIGN.md` §5)
- ชู: `equipment` PK = **serial_number**, `pm_record` ผูกประวัติ
- 🗣️ *อธิบายความสัมพันธ์หลัก: กลุ่ม→อุปกรณ์→ประวัติ PM, ผู้ทำ PM*

### สไลด์ 6 — Flow การทำงาน
- ใส่ภาพ Flow chart (จาก `docs/DESIGN.md` §4)
- 🗣️ *เดินตามเส้น: Login → แยกสิทธิ์ → เมนูตามสิทธิ์ → บันทึก PM → คำนวณรอบ*

### สไลด์ 7 — หัวใจระบบ: สูตรคำนวณรอบ PM
- รอบ: เครื่องพิมพ์/เครือข่าย = ทุก 3 เดือน · คอมพิวเตอร์ = ทุก 6 เดือน
- `next_due = (วัน PM ล่าสุด | วันเริ่มใช้งาน) + รอบของกลุ่ม`
- สถานะ: เลยกำหนด(แดง) / ใกล้ครบ ≤30 วัน(เหลือง) / ปกติ(เขียว)
- 🗣️ *จุดนี้คือ "เชิงป้องกัน" — ระบบรู้เองว่าเครื่องไหนถึงรอบ*

### สไลด์ 8 — ฟีเจอร์: Login + แยกสิทธิ์ (RBAC)
- รหัสผ่าน hash (bcrypt) + JWT token
- **ADMIN** กำกับดูแล/ตั้งค่า/ดูรายงาน · **TECHNICIAN (ช่าง)** เป็นผู้ลงมือบันทึก PM
- *ตามนโยบาย: ผู้ดูแลไม่ทำ PM เครื่องเอง — เป็นหน้าที่ของช่าง*
- พนักงานลาออก = ปิดบัญชี (soft-delete) แต่ประวัติยังโยงชื่อผู้ทำได้
- 🗣️ *เน้น: แยกหน้าที่ชัด — ช่างทำงาน ผู้ดูแลกำกับ + ตามรอยได้ว่าใครทำอะไร*

### สไลด์ 9 — ฟีเจอร์: บันทึก PM + Checklist
- เลือกอุปกรณ์ → Checklist ตามกลุ่มเด้งอัตโนมัติ (ผ่าน/ไม่ผ่าน + หมายเหตุ)
- บันทึกผู้ทำ + ค่าใช้จ่ายอัตโนมัติ + คำนวณรอบถัดไปทันที
- 🗣️ *Checklist ปรับได้เอง (admin) — ยืดหยุ่นตามอุปกรณ์*

### สไลด์ 10 — ฟีเจอร์: Dashboard & แจ้งเตือน
- การ์ดสรุป (เลยกำหนด/ใกล้ครบ/ปกติ) **คลิกกรองได้**
- Technician: **Popup งานรายวัน** เด้งเตือน *เฉพาะที่เลยกำหนด + ถึงกำหนดวันนี้* (ไม่รวมใกล้จะถึง)
- 🗣️ *ไม่ต้องไล่หาเอง ระบบดันงานมาให้*

### สไลด์ 11 — ฟีเจอร์: รายงาน + Export Excel
- 3 รายงาน: แผน PM รายเดือน / ประวัติรายเครื่อง / ค่าใช้จ่าย
- **Pie chart** สัดส่วนค่าใช้จ่าย + Export **Excel แต่งสวย อ่านง่าย**
- 🗣️ *ไฟล์ Excel โทนเดียวกับเว็บ ตัวเลขมีคอมมา เปิดใช้ต่อได้ทันที*

### สไลด์ 12 — จุดเด่นด้านคุณภาพ
- **Activity Log** — บันทึกทุก action สำคัญ (ใคร/ทำอะไร/เมื่อไร/IP)
- **Soft-delete** — ลบอุปกรณ์/ปลดพนักงาน แต่ประวัติ PM ไม่หาย
- **UI สบายตา** (ธีม Teal/Sage minimal) · **Docker** รันคำสั่งเดียว
- 🗣️ *ไม่ใช่แค่ใช้ได้ แต่ดูแล/ตรวจสอบย้อนหลังได้จริง*

### สไลด์ 13 — 🖥️ Live Demo
- สไลด์เปล่า/หัวข้อ "สาธิตการใช้งาน" → สลับไปเบราว์เซอร์
- 🗣️ *"เดี๋ยวสาธิตการทำงานจริงให้ดูครับ/ค่ะ"*

### สไลด์ 14 — สรุป & ต่อยอด
- ทำครบตามโจทย์ ✅ + ทำเกิน (Login/Checklist/Audit/รายงานกราฟ)
- ต่อยอด: หน้าจัดการผู้ใช้/ตั้งค่ากลุ่มในเว็บ, แก้ไขรายการ PM, แจ้งเตือนอีเมล
- 🗣️ *ปิดด้วยคุณค่า: ลดการลืมรอบ PM + มีข้อมูลตัดสินใจ* → ขอบคุณ / Q&A

## ส่วนที่ 2 — สคริปต์เดโม่สด (ลำดับคลิก ~6 นาที)

### ✅ เช็กลิสต์ก่อนเดโม่ (ทำก่อนขึ้นพูด)
- [ ] `docker compose up -d` แล้ว — เปิด http://localhost:4000/api/health เห็น `{"ok":true}`
- [ ] เปิด http://localhost:5173 ค้างไว้ที่หน้า Login (ซูมเบราว์เซอร์ ~110–125% ให้คนหลังเห็น)
- [ ] เตรียม 2 บัญชี: `admin/admin123` · `staffa/staff123`
- [ ] (แนะนำ) มีข้อมูล PM ตัวอย่างหลายกลุ่ม เพื่อให้ Dashboard/Pie ดูมีชีวิต — *ขอให้ผมช่วยสร้าง sample ให้ก่อนได้*
- [ ] เปิด SSMS ค้างไว้ (เผื่อโชว์ Activity log) — ไม่บังคับ

### 🎬 ลำดับสาธิต

**1) เข้าสู่ระบบ (ผู้ดูแล) — 30 วิ**
- หน้า Login → ใส่ `admin / admin123`
- 🗣️ *"รหัสผ่านเก็บแบบ hash ไม่ใช่ plaintext, ออก token ตามสิทธิ์"*

**2) Dashboard — 1 นาที**
- ชี้การ์ดสรุป → **คลิกการ์ด "เลยกำหนด PM"** → ตารางกรองให้ทันที → กด "ล้างตัวกรอง"
- 🗣️ *"ระบบคำนวณรอบเองจากสูตร เห็นทันทีว่าเครื่องไหนต้องทำก่อน"*

**3) จัดการอุปกรณ์ — 1 นาที**
- เมนู "จัดการอุปกรณ์" → ค้นหา SN → กด "เพิ่มอุปกรณ์" โชว์ฟอร์ม (ไม่ต้องบันทึกก็ได้)
- ลบอุปกรณ์ 1 ตัว → ชี้ข้อความ *"ซ่อนจากรายการ แต่ประวัติ PM ยังอยู่"*
- 🗣️ *"ลบแบบ soft-delete — ข้อมูลย้อนหลังไม่หาย"*

**4) ผู้ดูแลตรวจสอบประวัติ PM (อ่านอย่างเดียว) — 1 นาที**
- เมนู "บันทึกผล PM" → ชี้ตาราง **ประวัติการทำ PM** (เรียงล่าสุด→เก่า)
- **คลิกแถวประวัติ** → Popup รายละเอียด + ผลตรวจ checklist รายข้อ + ผู้ดำเนินการ
- 🗣️ *"ผู้ดูแลมีหน้าที่กำกับ/ตรวจสอบ — ดูได้ว่าช่างคนไหนทำเครื่องไหน ผลตรวจเป็นยังไง **แต่ผู้ดูแลไม่ลงมือ PM เอง เป็นหน้าที่ของช่าง**"*

**5) รายงาน + Excel — 1 นาที**
- เมนู "รายงาน" → สลับ 3 แท็บ → แท็บค่าใช้จ่าย โชว์ **Pie chart**
- กด **Export Excel** → เปิดไฟล์ที่โหลด → ชี้: หัวเขียวเข้าธีม, ตัวเลขมีคอมมา, อ่านง่าย
- 🗣️ *"รายงานตรงสเปก ดาวน์โหลดเอาไปใช้/ส่งต่อได้ทันที"*

**6) สลับเป็นช่าง — บันทึกผล PM (ไฮไลต์) — 2 นาที**
- ออกจากระบบ → login `staffa / staff123`
- **Popup งาน PM วันนี้เด้งทันที** → ชี้ว่าไม่มีเมนู Dashboard (สิทธิ์ต่างกัน)
- กด "บันทึก PM" จากใน popup → เด้งไปฟอร์มพร้อมเลือกเครื่องให้
- **Checklist เด้งอัตโนมัติตามกลุ่ม** → ติ๊ก ผ่าน/ไม่ผ่าน + ใส่หมายเหตุ 1 ข้อ → กด "บันทึก PM"
- ชี้: ค่าใช้จ่ายมาเอง, **ผู้ดำเนินการ = ช่างที่ login (ไม่ใช่ผู้ดูแล)**, ประวัติอัปเดต, รอบถัดไปคำนวณใหม่
- 🗣️ *"คนลงมือจริงคือช่าง — เปิดมาเห็นงานของวันเลย บันทึกครั้งเดียว ระบบเก็บว่าใครทำ + ผลเช็กแต่ละข้อ + คำนวณรอบถัดไปให้"*

**7) (ถ้ามีเวลา) Audit log**
- SSMS: `SELECT TOP 20 * FROM activity_log ORDER BY log_id DESC`
- 🗣️ *"ทุกการกระทำสำคัญถูกบันทึก ตรวจย้อนหลังได้"*

### 🧯 แผนสำรอง (ถ้าเดโม่มีปัญหา)
- เว็บไม่ขึ้น → `docker compose restart web` แล้ว refresh / มีภาพหน้าจอสำรองในสไลด์
- ข้อมูลน้อยไป → เตรียม sample PM ไว้ก่อนเดโม่ (ดูเช็กลิสต์)
- พูดคุมเวลา: ถ้ากระชั้น ตัดข้อ 7 และ 3 (ส่วนเพิ่มอุปกรณ์) ออกก่อน
