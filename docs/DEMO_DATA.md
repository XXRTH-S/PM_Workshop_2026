### ทำไมเลือก commissionDate = 15/02/2026?

- รอบ PM เครื่องพิมพ์ = **3 เดือน** → next_due = `15/02/2026 + 3 เดือน` = **15/05/2026**
- วันนี้ (2026-05-19) > 15/05/2026 → **เลยกำหนดมา ~4 วัน** → สถานะแดง 🔴
- เครื่องเดโม่นี้จะเด้งขึ้น **Dashboard ทันที** + เห็นในการ์ด "เลยกำหนด PM" → โชว์ค่าของระบบได้เต็มที่

## 🎯 จุดเด่นที่ฟังก์ชันนี้แสดง (ไว้ตอบ Q&A)

- **Validation** — กลุ่ม / ชนิด / SN / ชื่อ ห้ามว่าง (มี * แดงในฟอร์ม)
- **Auto-calc:** เลือกกลุ่ม → ระบบรู้เองว่ารอบกี่เดือน + ค่าใช้จ่ายเท่าไร (ไม่ต้องกรอกเอง)
- **PK = SN immutable** — เมื่อบันทึกแล้ว แก้ SN ไม่ได้ (ลองกด "แก้ไข" → ช่อง SN จะ disabled พร้อม tooltip)
- **Soft delete + Revive** — ลบ DEMO-PR001 → หายจากรายการ → เพิ่ม SN เดิมใหม่อีก → **กู้คืน** พร้อมประวัติเดิม (ถ้าเคยบันทึก PM ไว้)
- **Search:** ค้น "DEMO" ในช่องค้นหา → เห็นทั้ง 3 ตัวเรียงกันทันที (ทดสอบฟังก์ชันค้นหา)

## 🧹 ล้างข้อมูลเดโม่หลังนำเสนอ

วิธีง่ายสุด: ใช้ฟังก์ชันลบในระบบเอง (soft delete) — ไม่ต้องล้าง DB

1. หน้าจัดการอุปกรณ์ → ค้น `DEMO` → กดปุ่ม 🗑️ ลบทีละตัว (3 ตัว)
2. ระบบ soft-delete (ซ่อนจากรายการ แต่แถวยังอยู่ใน DB ด้วย status=DELETED — ประวัติ PM ของ DEMO-PR001 ก็ยังอยู่)
3. ถ้าอยากให้หายจริง: บอกผมหลังเดโม่ จะลบจริงให้ + ล้าง pm_record ของ DEMO-* ทิ้งด้วย

> 💡 หรือ rebuild Docker ใหม่ (`docker compose down -v && up --build`) → seed reset เป็นค่าตั้งต้น (37 อุปกรณ์เดิม) — แต่จะกระทบข้อมูลเดโม่อื่นด้วย ไม่แนะนำถ้ายังไม่เดโม่จบ
